# Dorm 开发记录

## 原始 Prompt 摘要

- 以 Flutter 和 Dart 为高校 AIGC 应用创新大赛实现可操作的寝室协作原型。
- 首先检测 WSL2，优先在 Linux 原生工作目录交付 Linux x86_64，再处理 Windows x86_64 与 Android ARM64。
- 公共账本优先，金额按分精确分摊，区分消费和转账。实现自动卫生轮换、打卡、换班与公共物资采购账单。
- 缺少工具链时提供对应发行版的安装命令，由用户安装。分析、测试、构建和启动结果以实际命令为准。

## 维护与人工复核

- 检查固定小数与整数分的转换以及付款方、参与方和实际转账的对应关系。
- 用真实宿舍数据试用前，核对系统日期和成员名单。试用后关闭再打开以检查数据保留。
- Windows 建议在目标主机从原生目录验证完整 Release 目录。Android 建议在 ARM64 真机验证输入法、返回键、打卡、安装和数据保留。
- 多设备同步接入前需要补充身份、共享规则、离线冲突处理、版本迁移和操作审计约定。

## 设备 SSH 密钥迭代

用户要求将 Git 和密钥管理放入应用。DormOS 沿用随包发布的 libgit2 和 SSH 运行库，通过 Dart cryptography 生成 Ed25519 密钥，并按 OpenSSH 格式编码。设备私钥沿用本地凭据目录的操作系统访问限制。仓库配置记录密钥来源，数据库升级保留原先导入密钥的默认行为与同步基线。界面可生成设备密钥、复制公钥并选择同步凭据。回归用例覆盖界面复制、设备密钥复用、旧版配置迁移和本地 Git 同步流程。

## .dorm 邀请迭代

用户要求将仓库和凭据打包成可快速分享的文件。实现版本化的 .dorm 格式，默认仅包含仓库地址。共享私钥时，用随机盐和 PBKDF2-HMAC-SHA256 派生邀请密钥，再以 AES-256-GCM 加密私钥和原 SSH 口令。仓库地址经认证数据绑定。导入后通过现有配置表单确认，并沿用本地凭据保护。回归测试覆盖文件往返、大小和结构限制、错误口令及仓库字段篡改。

## 账单个人费用迭代

用户要求同一笔垫付中区分均摊的公共开销和指定成员个人开销。公共费用继续按整数分均摊，再将每人个人费用并入其应付。迁移为历史分摊补零，保持原金额、付款人与实际转账。Git 快照没有个人费用时沿用旧格式，有个人费用时写入新版字段。验证覆盖个人费用独立归属、部分结算、旧数据库与双端 Git 同步。

## 云同步代理迭代

用户要求支持 SOCKS 与 HTTP 代理。实现 SOCKS5 和 HTTP CONNECT，支持可选用户名和密码。由于内置 Git 使用 SSH，Dart 为单次 Git 操作建立临时回环隧道，再只改写内存中的拉取和推送端点。SSH 指纹仍按 GitHub 固定指纹核验。代理设置沿用本机凭据目录，仓库和邀请文件无需迁移。

## 统一设置与公钥显示

将外观、成员、卫生任务和云同步集中到顶部齿轮入口。宽屏采用双栏，窄屏采用单列。云同步按连接、设备密钥、代理与邀请组织，公钥在界面以星号遮挡中段。Widget 回归测试检查遮挡后的展示、完整公钥复制、设置导航与主题切换。

## 品牌更名

自 v0.8.0 起，应用名称为 Dorm，全称使用用户指定的 Dorm Organizes Roomates' Matters。更新了界面、Windows 程序与文件属性，以及 Linux 和 Android 的可见名称。Windows 数据存储沿用旧版路径，因此可以读取原有数据库、SSH 凭据和代理设置。仓库同步标识和 .dorm 邀请格式亦延续使用。

## 分层设置与数据工具

按用户反馈将设置改成桌面的分类栏与详情区、窄屏的分类列表与详情页。主题保存在独立的本机偏好表，继续使用现有业务库与同步协议。账单页增加筛选、CSV 导出和待付清单。SQLite 在线备份复制一致的数据视图后移除同步配置。测试覆盖分类导航、主题、筛选、CSV 转义和备份内容。

## 寝室事务和批量结算

新增独立事务看板，记录负责人、优先级、截止日、状态和归档。结算中心将同一付款方向的一笔实际转账按所选账单余额依次分摊，批次和账单转账在同一事务中更新，保存前比对当前余额。首次使用新模块才输出 v3 云快照。测试覆盖旧库迁移、新数据双端同步、余额变动拦截、事务状态和两端界面流程。

## 月度账务分析与采购清单

月度统计读取账单和个人份额，按账单创建日期归入本机自然月。公共预算只比较公共支出。采购清单结合共享的采购状态、库存及本机低库存阈值，增加库存和更新入库状态使用同一条 SQL。启动、筛选、均摊、事务视图、预算和库存偏好复用本机设置表，不改变同步格式。测试覆盖报表计算、预算设置、采购状态、入库边界和偏好恢复。

## 局域网工作台

应用在手动开启时绑定 IPv4 接口，通过自身资源提供桌面和移动浏览器可用的工作台。网页写入由现有控制器调用仓库，复用账务校验、界面刷新以及已经启用的云同步。设置仅记住端口。每次启动生成临时访问码和会话令牌，重置时同时轮换两者。

使用真实 HTTP 回环连接验证静态资源、鉴权、同源检查、访问码重置和四个模块写入。

## 寝室工具箱与仓库二维码

抽签和分组共用随机分配逻辑。工具可直接载入启用成员，也支持自定义名单。功能测试验证重复输入、人数不整除的分组和实际界面操作。

二维码沿用 .dorm 邀请的加密凭据与解锁路径。使用 ZXing 的纯 Dart 实现编解码，Windows 用户可通过二维码图片或扫码文本导入。自动化测试使用实际生成的 SSH 密钥，验证 PNG 编解码与相同私钥的恢复。

## Windows 安装包

从已验证的 Windows x64 Release 生成当前用户安装向导。安装器沿用固定的应用标识，并随应用部署 Visual Studio 的 x64 Redistributable，原有数据继续由 Dorm 在用户数据目录管理。使用官方便携编译器 Inno Setup 7.1.1，并核对其签名和发布哈希。

在 Windows 实测安装、覆盖安装和卸载。核对发布目录中的 25 个文件与已安装的对应文件哈希一致，确认开始菜单和卸载注册正确，原有 SQLite 文件哈希保持一致。

## 启动速度

先打开本地账本并渲染所选启动页面，再发起后台云同步。已升级至当前架构的 SQLite 数据库直接打开，旧版本和首次启动仍在事务中初始化。

Widget 测试模拟初次拉取延迟八秒，验证期间可查看历史账单及新建账单，连接恢复后可上传新增记录。仓储测试验证另一连接持有写锁时仍能打开和读取已迁移数据库。

## 局域网扫码分享

局域网页在服务器运行期间可通过地址直接打开，设置提供室友访问地址的二维码并支持保存 PNG。服务器只接受本次监听对应的地址和端口，并校验浏览器的跨站写入。需由使用者手动开启服务。

自动化测试使用实际生成的二维码和回环 HTTP 验证地址往返、直接访问、业务读写及跨站请求拒绝。

## Android 0.13.2 构建验证

使用现有 WSL2 Debian、JDK 21、Android SDK 和 Gradle 缓存构建 Android ARM64 Release。默认 Gradle 进程因 WSL 内存不足被终止，第二次构建用 1536 MiB Java 堆、单 worker 并在进程内编译 Kotlin，成功生成 APK。按 ABI 格式保留旧版版本号规则。

校验 APK 版本号 2018、开发签名和 8 个 AArch64 原生库。与已交付的 0.2.0 APK 包名及签名一致，版本号可升级。尚未进行 Android 设备运行测试。

## Android 摄像头扫码

Android 邀请导入和局域网加入入口共用相机扫码页。使用随 APK 打包的条码识别引擎，仓库邀请复用原有解锁确认流程，局域网地址交给浏览器打开。扫码页处理相机权限、前后台切换和销毁。

53 项测试通过，其中扫码界面测试以模拟相机事件验证二维码检测、错误提示、正确结果和相机释放。Android ARM64 Release 包已核实相机权限、扫码引擎、签名及原生库架构。无连接设备可做真机验证。

## 工具箱动画与导航重构

工具箱拆分成抽签与掷骰两个独立组件。抽签与分组统一校验候选项，修复重复候选和分组人数不足时的反向区间提示。随机结果一次生成，洗签与翻滚仅展示过程。组件在动画期间锁定同一个操作，并遵循系统减少动态效果设置。

导航使用启动页枚举定位页面。窄屏支持在抽签和骰子之间切换，并保留本页操作结果。测试覆盖等待揭晓、控件锁定、减少动态效果、窄屏切换和窗口缩放。

## 立体骰子和翻牌揭晓

骰子按立方体六个面投影。透视、光照与阴影跟随同一次翻滚，停止时把随机结果所在的面转向用户。抽签先洗牌，再选择牌张并翻面揭晓，复制操作在揭晓流程完成后可用。减少动态效果时仍直接显示结果。

检查了实际渲染的关键帧。测试覆盖洗签、抽牌、揭晓、滚动中间帧以及骰面和结果文本的一致性。
