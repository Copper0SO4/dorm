## 一、项目背景与需求分析

### 1.1 场景痛点
高校寝室（通常 4–6 人）在日常共同生活中存在高频、碎片化但易引发摩擦的协作需求，传统解决方式（微信群文字接龙、零散记账小程序、口头约定值日）存在以下痛点：
1. **公共账目混乱与结算繁琐**：买水、聚餐、采购日用品时，常出现“一人垫付公共开销 + 顺便替某位室友代付个人物品”的混合账单。传统记账难以在同一笔账单中同时处理“公共均摊”与“个人代付”，且累积多笔欠款后缺乏清晰的批量核销机制，月末算账容易扯皮。
2. **卫生排班易遗忘、调班难**：口头排班或静态表格无法自动轮换，遇到某位室友临时外出或已离寝停用，往往需要手动重排整张表，缺乏历史打卡追溯。
3. **公共物资重复购买或断货**：卫生纸、垃圾袋等公共耗材余量不透明，谁买了、花了多少钱、是否已入库与账本脱节。
4. **跨设备与网络环境割裂**：寝室成员既在手机端（Android）随手记录，也常在电脑端（Windows / Linux）集中对账或开局域网工具；校园网或无网环境下依赖纯云端 SaaS 工具往往体验受限。

### 1.2 目标用户与需求定位
* **核心用户**：高校寝室成员（4–6 人小团队）、合租室友。
* **核心诉求**：
  * **离线优先、隐私可控**：业务数据保留在本地，不强制绑定商业服务器，不上传敏感消费隐私。
  * **轻量共享、按需同步**：支持局域网扫码即用，也支持基于私有 Git 仓库的端到端加密云同步。
  * **功能闭环**：从记账、排班、采购、事务看板到寝室娱乐破冰工具，一站式覆盖高频需求。

## 二、解决方案与产品设计

### 2.1 产品概述
**Dorm**（全称 *Dorm Organizes Roomates' Matters*，包名 `dormos`，当前版本 `0.18.14+41`）是一款**离线优先、支持跨端协同的寝室事务与生活管理应用**，现已支持 **Windows x64、Android ARM64、Linux x64** 原生客户端及 **局域网网页工作台**。

### 2.2 五大核心模块与业务闭环
1. **公共账本与结算中心（输入 → 精确分摊 → 批量核销 → 统计导出）**
   * **混合记账**：同一笔账单支持填写“公共费用（按参与成员整数分精确均摊，余分按成员 ID 升序分配）”与“个人代付明细”，自动计算每位成员应付总额。
   * **结算中心**：按付款方向汇总待结清账单，支持登记实际转账并从最早账单起依次核销，支持部分还款与结算历史追溯。
   * **月度分析与导出**：展示近 6 个月公共支出、个人代付、待结清趋势及本机月度预算对比；支持账单筛选、待付清单复制与 CSV 导出。
2. **卫生排班（任务配置 → 自动轮换 → 打卡/换班）**
   * 支持每日/每周任务与起始日期配置，按成员游标自动生成排班；支持日历月视图追溯历史、待完成班次改派或互换、完成打卡留痕。
3. **公共物资（库存登记 → 低库存提醒 → 采购入账联动）**
   * 维护物资名称、分类、数量、存放位置与采购状态；支持自定义低库存阈值，点击“记录采购”可在单事务内同步生成账本开销并更新采购状态，实现物资与账务关联追溯。
4. **寝室事务看板（派发 → 跟进 → 归档）**
   * 管理报修、活动筹备等共同事项，支持负责人指派、优先级标记、截止日期、三状态看板（桌面并排/窄屏切换）与归档恢复。
5. **寝室工具箱（决策工具 + 双网络斗地主）**
   * **实用决策工具**：抽签（透视 3D 翻牌揭晓）、随机分组（3D 舞台名牌飞入动画）、立体骰子与数字炸弹，均遵循系统“减少动态效果”设置。
   * **原生/网页斗地主**：支持 2–8 人、1–4 副牌、经典/癞子玩法与记牌器；支持**局域网自动发现 + 网页匿名扫码入座**，以及 **API 电脑/AI 提示与牌桌聊天**（可接入 DeepSeek / OpenAI 兼容 / Anthropic 接口，自带超时降级至本地规则出牌）。

### 2.3 多端协同与数据安全设计
* **本机离线存储**：采用 SQLite（`dormos.sqlite3`）持久化，金额全部以**整数分**存储，避免浮点精度误差；支持导出 `.dormbak` 本地备份。
* **可选 GitHub 云同步**：基于 `dormos-data` 专用分支同步快照，内嵌 `libgit2` 与 `Ed25519` 设备密钥生成；支持 `.dorm` 口令加密文件（PBKDF2-HMAC-SHA256 + AES-256-GCM）及二维码分享仓库凭据；支持冲突并列对比解决；支持 HTTP CONNECT / SOCKS5 代理。
* **局域网工作台**：桌面端一键开启本地 HTTP 服务并生成访问码与二维码，手机扫码即可在浏览器共同记账、排班、维护物资与事务。

## 三、技术实现路径与系统架构

### 3.1 技术栈选型
| 层级 | 选型与核心依赖 | 作用说明 |
| --- | --- | --- |
| 跨平台框架 | Flutter (`>=3.50.0`) / Dart (`>=3.14.0`) | 单一代码库覆盖 Windows、Linux、Android |
| UI 规范 | Material 3 (`material_ui`) + 内置 `NotoSansSC` | 宽屏侧边导航 / 窄屏底部导航自适应，保证无中文字体环境正常显示 |
| 本地持久化 | `sqlite3`、`path_provider`、`file_selector` | 事务型本地数据库、跨平台数据目录解析与文档保存 |
| 云同步与加密 | `git2dart`、`cryptography`、`crypto` | 原生 Git/SSH 传输、Ed25519 密钥、AES-GCM 加密与主机指纹校验 |
| 扫码与局域网 | `zxing2`、`mobile_scanner`、`dart:io` HTTP/UDP | 二维码编解码、Android 相机扫码、局域网服务与 UDP 房间发现 |

### 3.2 分层架构设计
* **`lib/domain/`（纯 Dart 领域层）**：封装整数分账本计算（`ledger.dart`）、批量核销（`settlement.dart`）、排班轮换（`schedule.dart`）、采购模型（`procurement.dart`）、事务看板（`matters.dart`）、抽签分组（`draw.dart`、`party_tools.dart`）、同步协议（`cloud.dart`）等纯逻辑，与 UI 和平台解耦，便于单元测试全覆盖。
* **`lib/data/`（数据与传输层）**：实现 SQLite 仓储（`sqlite_repository.dart`）、跨平台数据目录与环境变量覆盖（`local_directory.dart`）、GitHub 传输与代理隧道（`github_transport.dart`、`cloud_proxy.dart`、`cloud_sync.dart`）、凭据权限隔离（`ssh_vault.dart`）、邀请打包（`dorm_invite.dart`、`invite_qr.dart`）及局域网服务端（`lan_server.dart`）。
* **`lib/game/`（牌桌引擎与联机层）**：共用牌型判断、多副牌/连炸/癞子规则、本地出牌机器人、API 模型接入与超时容错（`bot_api.dart`）、UDP 局域网发现（`card_network.dart`）及 X25519+AES-GCM 加密的 Git 联机牌桌（`online_cards.dart`）。
* **`lib/ui/`（自适应界面层）**：依据窗口宽度自动切换宽/窄屏布局；桌面端支持 `Ctrl+1`~`Ctrl+5` 快捷切换主标签页、状态栏实时显示云同步状态、牌桌支持 `F11` 全屏。

## 五、创新点与实用价值

1. **工程化完成度高，真正实现“离线 + 轻云端 + 局域网”三模协同**：区别于依赖公网服务器的普通记账原型，Dorm 即使在无网环境也能完整运行，既可通过局域网即时协同，也可借助个人私有 GitHub 仓库实现零服务器成本的端到端加密同步。
2. **贴合高校真实混合消费的账务模型**：在同一账单事务内统一“公共分摊”与“个人代付”，结合整数分守恒算法和“按最旧账单依次核销”的结算中心，彻底解决小数误差与多笔混杂算账痛点。
3. **跨三端一致体验与桌面端深度适配**：不仅覆盖 Windows 与 Android，还借助 AI 辅助完成了 Linux（GTK3 / Wayland）桌面端移植与窗口/文件保存/快捷键等原生适配，兼容学生群体常用的多样化系统环境。
4. **AIGC 双重赋能**：既在**研发侧**深度应用 AI 编码助手完成架构、移植、Bug 排查与测试验证；也在**应用侧**的休闲工具模块内置可配置的 LLM API 托管与提示能力，兼顾实用性与趣味性。

### 7.3 AI 生成 → 人工核查 → 迭代修正真实案例（重点展示）
以下案例真实记录了“AI 辅助生成后，通过实测与代码审查发现缺陷并完成闭环修复”的过程：

1. **案例一：Linux 文件保存未自动补全扩展名问题（`lib/ui/save_document.dart`）**
   * **问题发现**：Linux 移植初期，Windows 原生保存对话框会自动补全文件后缀，但 Linux 下的 GTK3 `GtkFileChooserDialog` 在用户仅输入文件名（如 `backup`）时直接返回无后缀路径，导致导出校验触发 `InputException` 报错。
   * **AI 定位与修复**：定位到 `save_document.dart` 的后缀校验逻辑，改为当所选文件名不含 `.` 时自动补全 `.$extension`，同时保留“用户输入错误后缀时仍拦截提示”的防御检查。
   * **人工核查**：在 Linux Release 实机导出 CSV 与 `.dormbak` 备份文件，验证无后缀输入与错误后缀输入均符合预期。

2. **案例二：Android 头像选择与局域网 UDP 发现异步竞态 Bug（全平台隐患排查）**
   * **问题发现**：审查跨平台文件选择与网络模块时发现两处隐患：（1）`lib/ui/member_identity.dart` 的 `pickAvatar()` 在 Android SAF 文件选择器下传入严格扩展名过滤可能导致部分相册文件无法选中；（2）`lib/game/card_network.dart` 中 `CardDiscovery.start()` 在 `await NetworkInterface.list(...)` 挂起期间若外部调用了 `stop()`，恢复后仍会操作已关闭的 UDP Socket。
   * **AI 修复与核查**：在 Android 端将 `acceptedTypeGroups` 放宽为 `const []`；在 `NetworkInterface.list` 返回后增加 `if (_listener != socket) return;` 状态守卫，并通过 `flutter analyze` 与全量测试验证无回归。

3. **案例三：Linux 桌面端全屏通道与同步状态交互优化**
   * **迭代过程**：从历史提交恢复 `linux/` Runner 后，原生侧缺少 `dorm/cards/window` 的全屏 MethodChannel 实现，且桌面主界面侧边栏仅静态显示“本机存储”，用户无法直观感知后台云同步状态。
   * **修正落地**：在 `linux/runner/my_application.cc` 实现基于 `gtk_window_fullscreen` / `gtk_window_unfullscreen` 与 `window-state-event` 监听的通道（含 `dispose` 资源清理）；在 `lib/ui/card_table.dart` 开放 `TargetPlatform.linux` 的 `F11` 全屏与紧凑手牌间距；在 `lib/ui/app.dart` 增加 `Ctrl+1`~`Ctrl+5` 全局标签快捷键，并将侧边栏状态组件绑定至 `CloudSync` 实时状态（如“正在云同步…”、“已启用云同步”、“云同步有冲突”）。同时在测试中刻意避免使用 `AnimatedSwitcher` 破坏原有 Widget 测试帧断言，确保 161 项测试全数通过。

4. **案例四：Widget 弹窗布局与中文字体缺失修正（历史迭代）**
   * **问题发现**：早期在 Debian/Linux 环境测试时出现中文方块乱码，且端到端 Widget 测试暴露采购历史弹窗与 `LayoutBuilder` 尺寸计算冲突。
