# Dorm

**Dorm Organizes Roomates' Matters**

Dorm 是寝室公用账本、卫生排班和物资清单。首次打开应用时，账本和清单均为空。添加实际寝室成员后即可开始使用。数据保存在本机 SQLite，支持离线操作和可选的 GitHub 云同步。

## 支持平台

- Windows x64。运行安装包，或解压完整免安装目录并运行 Dorm.exe。
- Android ARM64。安装 APK。在 Dorm 房间入座后使用横屏牌桌，离桌后恢复系统方向设置。
- 网页。通过 Windows 或 Android 房主分享的局域网链接打开斗地主牌桌，浏览器访客可以匿名入座。

## 使用方式

| 模块 | 操作 |
| --- | --- |
| 公共账本 | 打开「寝室成员」添加成员，再新建账单。填写公共费用和付款人，按需调整均摊成员。点「添加个人费用」给指定成员记一笔由本人承担的费用。账单详情可登记一笔或多笔实际转账，成员汇总显示累计应收、应付及未结清余额。 |
| 卫生排班 | 在「任务设置」添加每日或每周任务，选择开始日期。点击日历查看某日或整月，过去的月份可查看历史。待完成班次可改派或与同任务的其他待完成班次交换。 |
| 公共物资 | 录入名称、分类、数量、位置、备注和采购状态，按关键词、分类或状态查找。点击「记录采购」将支出记入总账，点击「采购账单」回看关联开销。 |
| 寝室事务 | 在看板上指派负责人、设截止日期、标记优先事项并跟进进度。完成事项可归档，也可从归档中恢复。 |

例如丙垫付 30 元公共餐费，三人均摊，另外替甲付了 8 元饮料。账单总额为 38 元，甲转给丙 18 元，乙转给丙 10 元。纯个人代付时可将公共费用留空。个人费用明细会随账单同步，使用同一个 GitHub 仓库的设备需要升级至 v0.5.0 才能读取含个人费用的快照。

宽屏显示侧边导航和账单表格，窄屏显示底部导航和卡片。点击右上角齿轮打开「设置」。宽屏在左侧选分类，窄屏点分类进入详情。「外观」中的主题选择会保存在本机。成员和卫生任务归在「寝室管理」，GitHub、SSH 密钥、代理和邀请归在「云同步」。

打开账单详情可点击「删除账单」并确认。删除后，该账单及关联的分摊和转账会从账本、余额及结算历史移除，应用内无法撤销。局域网工作台也提供这个操作。使用 GitHub 同步的成员需要升级到 Dorm 0.12.1 或更高版本才能读取包含已删除账单的快照。

### 寝室工具箱

抽签、随机分组和骰子可从工具箱直接切换。抽签和分组默认使用在用室友名单，可编辑候选并用加减按钮调整数量。抽签使用实验性 3D 签牌和透视运镜，揭晓后保留签面和完整结果。多抽时签牌依次翻开，超过四项时，按抽取顺序把结果合并到四张签牌上，下方可查看或复制完整名单。分组显示预计人数，启动后成员名牌在 3D 舞台打散并飞向各组。人数较多时舞台会分批显示，结束后可查看和复制完整名单，各组人数最多相差一人。局域网网页也支持分组动画。动画可跳过，也会尊重减少动态效果和墨水屏模式。骰子保留立体翻滚，开启系统减少动态效果时直接显示结果。首次记账可从「添加室友并记账」完成成员登记后直接继续。

「数字炸弹 → 编辑惩罚」支持逐行填写、去重和恢复默认。原生端名单保存在本机设置，局域网页名单保存在当前浏览器。

### 结算中心与事务看板

「公共账本 → 结算中心」按付款方向列出待付账单。选择账单并登记本次实际转账金额，Dorm 会从最早的账单开始核销。支持部分金额，在「结算记录」可展开查看分摊到每张账单的金额。登记只更新账本，不会发起支付。

「寝室事务」适合记录报修、活动准备等共同事项。支持负责人、截止日期、优先处理、完成时间与归档。桌面宽屏并排列出三个状态，窄屏可在状态之间切换。

### 月度预算与公共采购

「公共账本 → 月度分析」汇总每月的公共支出、个人代付、当前待结清金额和付款人垫付情况，展示近六个月趋势。「设置 → 账本偏好」可设本机的月度公共预算。预算按本月公共支出计算。

「公共物资 → 采购清单」汇总手动待采购、低库存和采购中的物资。可复制清单、标记采购中、记录采购账单，或在到货后增加库存。「设置 → 物资偏好」可调整低库存阈值或关闭低库存提醒。

启动页面、账本筛选、新账单均摊默认项和事务视图均可在「设置」调整。这些偏好保存在本机，应用在相应页面下次打开时使用新的默认选项。

### 账单查找、导出与备份

「账单历史」可按账单名称、付款人或关联物资搜索，也可筛选本月或待结清账单。「导出当前结果」生成 CSV，在「设置 → 本机数据」也可以导出全部账单。账单详情提供「复制待付清单」，方便转发当前余额。

「设置 → 本机数据 → 创建本地备份」生成 .dormbak 文件，其中保存成员、账单、转账、排班及物资。寝室事务与批量结算历史也会包含在备份中。备份采用 SQLite 格式，排除云同步配置与本机凭据。应用内提供导出，恢复可在应用完全退出后先另存现有数据库，再将备份复制到原位置并命名为 dormos.sqlite3。

### 更换配置目录

在 Windows 版打开「设置 → 本机数据 → 更换配置目录」。选择一个可写的本机文件夹，Dorm 会在其中创建 Dorm 子目录。关闭所有 Dorm 窗口后再打开，数据库、偏好、设备身份和 SSH 配置会迁入新位置，原目录留作备份。设置页会显示当前目录和待迁移位置，也可以取消待迁移的选择。

### 恢复出厂设置

打开「设置 → 本机数据 → 清空数据与恢复出厂设置」。清空本机寝室数据和偏好时，可以分别勾选两项。未配置 GitHub 仓库时，弹窗仍会显示选项和配置入口提示。

- **保留仓库配置**保留仓库地址和所用的 SSH 密钥。仅勾选此项时，下次同步会重新下载远端仍有的寝室数据。
- **清空远程仓库的 Dorm 数据**将 GitHub 上的寝室数据和在线牌桌快照写为空。两项一起勾选，可以清空本机与远端后继续使用同一个仓库。

## GitHub 云同步

1. 创建私有 GitHub 仓库。在 Dorm 右上角打开「设置」，找到「GitHub 云同步」，点击「生成 SSH 密钥」，再点击「复制公钥」。
2. 在仓库的 Settings → Deploy keys 添加这段公钥，勾选 Allow write access。不同设备各自生成密钥，都可以连接同一个仓库。 [GitHub Deploy keys](https://docs.github.com/en/authentication/connecting-to-github-with-ssh/managing-deploy-keys)
3. 回到 Dorm，点击「配置仓库」，输入仓库地址与操作者名称，保留「使用设备 SSH 密钥」，然后保存。仓库的 HTTPS 地址会转换为 SSH 地址，操作者和可选邮箱会保留并用于 Git 提交。已有 OpenSSH 私钥仍可通过「粘贴 SSH 私钥」导入，若私钥已加密，请填写口令。

Dorm 随应用提供 Git 和 SSH 运行库，生成密钥及同步均可直接在应用中完成。生成的 Ed25519 私钥存放在本机受操作系统权限保护的应用目录。界面以星号遮挡公钥中段。「复制公钥」可将完整公钥复制到剪贴板。断开仓库后仍可继续使用该设备密钥。

### 代理设置

在「GitHub 云同步」点击「代理设置」，启用后选择 HTTP CONNECT 或 SOCKS5，再填写本机或网络代理的主机、端口。代理要求认证时，填写用户名和密码。云同步通过代理连接 `ssh.github.com:443`，拉取和推送继续核验 GitHub SSH 主机指纹。代理配置保存在本机受权限保护的应用目录，不随快照或 `.dorm` 分享。关闭代理后恢复直连。

### 分享 .dorm 邀请

仓库配置完成后，在「GitHub 云同步」点击「导出 .dorm」。默认导出仓库地址，接收者可使用自己的 SSH 密钥。如果需要共享已授权的私钥，勾选「用口令加密后共享当前 SSH 私钥」，输入独立的邀请口令。文件与口令应通过不同渠道发送。能解锁该文件的成员会获得这把密钥对应的 GitHub 权限。

接收者在同一页面点击「导入 .dorm」，选择文件并按提示输入邀请口令，再核对仓库地址、填写自己的操作者名称并保存。邀请不包含寝室业务数据或发送者身份。当前 Dorm 只有一套本机寝室数据，切换同步仓库前请核对目标。

### 分享仓库二维码

配置好可用的仓库密钥后，点击「云同步 → 分享仓库二维码」。保存二维码图片或复制扫码文本，把邀请码单独发给室友。接收方点击「导入邀请二维码」，选二维码图片或粘贴已复制的文本，输入邀请码并填自己的操作者名称。大家使用同一把仓库私钥，无需逐台录入公钥。若需撤换这把仓库密钥，需要重新邀请使用它的设备。

二维码图片只包含仓库地址和加密凭据。密钥过长时可使用 .dorm 文件分享。 在 Android 上可从「导入邀请二维码 → 摄像头扫码」直接扫描，随后输入邀请码。

### 同步行为

应用在打开本地界面后启动后台同步。本地写入后短延迟同步，运行时每 30 秒检查云端更新。数据只写入专用的 `dormos-data` 分支，其中的 `dormos.json` 保存业务快照。连接采用 GitHub 的 SSH 443 入口并核对官方主机指纹。 [GitHub SSH 443](https://docs.github.com/en/authentication/troubleshooting-ssh/using-ssh-over-the-https-port) · [主机指纹](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/githubs-ssh-key-fingerprints)

含寝室事务或批量结算的快照需要同步设备升级至 v0.10.0。没有使用这两个模块的快照仍保持原有版本。

本机和云端基于上次同步的快照自动合并独立改动。同一条记录的不同改动会在「解决同步冲突」里并列显示，可逐条保留本机或云端版本。首次连接已有两份不同数据时可选一份完整版本。合并会核对账单总额、转账余额和记录关联。

私钥与口令文件保存在应用数据目录的 `cloud-credentials` 下，依赖操作系统的当前用户目录权限或移动设备应用沙盒保护。该目录不进入 Git 分支、同步快照或 Android 系统备份。断开连接会移除此仓库在本机保存的私钥。可复制关闭应用后的 SQLite 文件备份本机数据。

## 局域网工作台

在宿舍电脑打开「设置 → 局域网服务器」，确认端口后点击「启动服务器」。点室友访问地址右侧的二维码图标，让同一网络里的室友扫码，或直接复制链接发给室友。打开后可直接操作工作台。二维码可保存为 PNG 图片。 Android 应用也可在「设置 → 局域网服务器 → 扫码加入工作台」用摄像头扫描室友分享的链接。

网页和桌面端共用数据库。室友可以新建含个人费用的账单、登记转账、生成排班和打卡、维护物资和采购，以及更新或归档事务。退出 Dorm 或点击「停止服务器」会结束服务，下次打开 Dorm 时需要手动启动。

Dorm 在所有 IPv4 接口监听，使用 HTTP。能访问该地址的人都可以读写数据，请在信任的局域网中使用。若 Windows 防火墙提示是否允许，选择专用网络。同一 Wi-Fi 上的访客隔离也可能阻止设备互访。

### Windows x86_64 构建

从同一个 Git 提交克隆到独立的 Windows 原生工作目录，使用对应版本的 Windows Flutter。Visual Studio 需要「使用 C++ 的桌面开发」工作负载及 MSVC x64、Windows SDK 和 CMake 工具。用 Windows 端的 `flutter doctor -v` 检查 Visual Studio。可以从 WSL 启动 `powershell.exe -NoProfile`。在 Windows PowerShell 中，将 `$bundle` 指向交付的 `Dorm-source.bundle`，并指定新的 Windows 工作目录和 SDK 路径。

```powershell
git clone --branch main $bundle $windowsWorktree
Set-Location -LiteralPath $windowsWorktree
git rev-parse HEAD
& $windowsFlutter doctor -v
& $windowsFlutter pub get --enforce-lockfile
& $windowsFlutter build windows --release
& '.\build\windows\x64\runner\Release\Dorm.exe'
```

在 x86_64 Windows 主机使用 x64 Flutter。Flutter 3.50 按 Windows 宿主架构选择构建目标。归档整个 `build\windows\x64\runner\Release`，其中包含程序、Flutter 引擎、插件 DLL 和数据文件。

### Windows x64 安装包

运行 `Dorm-Windows-x64-Setup-v<版本>.exe`，可自选安装路径并添加桌面快捷方式。默认装在当前用户的 `%LocalAppData%\Programs\Dorm`，开始菜单可搜索 Dorm。可在「设置 → 应用 → 已安装的应用」卸载。覆盖安装或卸载都保留 Dorm 的本机业务数据。

已有 Windows Release 时，在 Windows 侧运行以下命令打包。脚本使用 Inno Setup 7 和 Visual Studio 的 x64 Redistributable，将需要的 C++ 运行库放在应用目录。可以用 `-RuntimeDir` 指定 Visual Studio 的 `x64\Microsoft.VC*.CRT` 目录。

```powershell
.\tool\package-windows.ps1 -InnoCompiler $iscc -ReleaseDir $releaseDir -OutputDir $outputDir
```

### Android ARM64 构建

在 Debian 的同一 Git 提交使用 Linux Flutter、OpenJDK 21 和 Linux 版 [Android SDK Command-line Tools](https://developer.android.com/studio#command-tools)。JDK 负责运行 Gradle 与编译 Java，Android SDK 提供 API 36 的编译库及 APK 工具。可以请设备维护人运行 `sudo apt install openjdk-21-jdk-headless`，再将命令行工具解压至 `~/.local/opt/android-sdk/cmdline-tools/latest`。`bin/sdkmanager` 应直接位于该目录下。以下环境变量只用于当前终端。

```bash
export JAVA_HOME="$(dirname "$(dirname "$(readlink -f "$(command -v javac)")")")"
export ANDROID_HOME="$HOME/.local/opt/android-sdk"
export GRADLE_USER_HOME="$HOME/.cache/dormos-gradle"
"$ANDROID_HOME/cmdline-tools/latest/bin/sdkmanager" --sdk_root="$ANDROID_HOME" --licenses
"$ANDROID_HOME/cmdline-tools/latest/bin/sdkmanager" --sdk_root="$ANDROID_HOME" \
  "platform-tools" "platforms;android-35" "platforms;android-36" \
  "build-tools;36.0.0" "ndk;28.2.13676358"
```

Flutter 3.50 的 Android runner 使用 Gradle 9.5.0 和 API 36，最低设备版本为 API 24。锁定的 Android 路径插件通过 `jni` 依赖使用 API 35 和 CMake 编译 JNI，因此需要该版本的 NDK。Debian 13 的现有 CMake 和 Ninja 用于本机构建，若 Gradle 另有诊断，按诊断补齐对应组件。

```bash
flutter doctor -v
flutter pub get --enforce-lockfile
flutter build apk --release --target-platform android-arm64 --split-per-abi
unzip -Z1 build/app/outputs/flutter-apk/app-arm64-v8a-release.apk | grep '^lib/'
```

仅指定 Android ARM64 时，按 ABI 打包会生成一份 APK，版本号沿用已发布 ARM64 版本的规则，可按版本号升级。所有 `lib/` 下的 ABI 应为 `arm64-v8a`。Debug 构建面向调试，Release 构建采用发布优化，正式发布还需要专用签名或由 Google Play 管理应用签名。用开发签名签出的 Release APK 可用于内部安装验证。签名配置和密钥须保存在仓库外。构建及 ABI 检查与真机安装、启动和交互测试分别记录。

## 项目结构与数据

| 路径 | 内容 |
| --- | --- |
| `lib/domain/` | 跨平台业务模型、整数分金额、轮换规则及仓储接口 |
| `lib/data/` | SQLite schema、事务、状态更新及查询 |
| `lib/ui/` | Material 3 布局、页面和表单 |
| `test/` | 数据、业务规则和 Widget 测试 |
| `docs/development.md` | 开发与 AI 辅助记录 |

SQLite 文件位于平台的应用支持目录下 `dormos/dormos.sqlite3`。Windows 沿用早期版本在 `org.dormos/dormos` 下的应用支持目录。关闭应用后可以复制该数据库文件做备份。业务数据在同一台设备上重启后保留。

Dorm 随包提供 [Noto Sans SC](https://github.com/google/fonts/tree/main/ofl/notosanssc) 作为中文回退字体。字体按 SIL Open Font License 1.1 发布，许可文本保存在 `assets/fonts/OFL-NotoSansSC.txt`。

- 金额以整数分持久化。余分依成员 ID 升序分配。付款者若在参与名单中，其本人份额计入消费，免于给自己转账。累计应收和应付均按成员间实际债权统计。
- 每项卫生任务独立轮换。启用云同步时，设备使用相同的记录顺序。已生成班次保留原负责人，成员变动自下一未生成班次起生效。已停用成员的旧班次会标记状态，可手动改派。打卡记录保存完成时间。
- 创建采购账单时，待采购物资更新为采购中。到货后可手动调整库存和状态。删除物资会从清单隐藏该物资，关联账单及采购名称快照仍可追溯。
- 仓储接口与独立转账记录为接入 Supabase/PostgreSQL、撤销与审计预留扩展点。账本暂未提供债务抵消及修改历史账单的功能。

### 「我」和修改记录

打开主界面右上角的「我」，选择未被认领的室友。同步发现两台设备认领同一人时，双方会收到撤销结果并可重新认领。每台设备有固定设备码，可在「我」和「设置 → 寝室管理」查看。寝室管理可编辑成员姓名、头像并查看日志。

在账单详情选择「编辑账单」可调整名称、金额、付款人及分摊。已登记转账的账单保留付款人和既有转账，金额调整需要覆盖已付金额。账单修改记录显示对应设备码。旧版账单只会显示升级后生成的日志。启用 GitHub 同步的室友需先升级到支持格式 5 的版本。

### 斗地主

在「寝室工具箱 → 斗地主」进入原生大厅。本机与局域网房间可添加「本地电脑」或「API 电脑」填补座位；「本地电脑」按内置规则出牌，开启「电脑 API」后可添加「API 电脑」，每个需要判断的回合发送该电脑玩家的手牌与本局公开操作，由模型从合法动作中选择。默认使用 DeepSeek 的 `deepseek-flash` 和低思考等级，也支持 OpenAI 兼容或 Anthropic。单次请求最多等待 45 秒。前两次超时由本地电脑代打当前回合，后续回合仍会尝试 API。同局第三次超时后，自动出牌由本地电脑接管，下一局恢复尝试。其他调用错误只影响当前回合，手动 AI 提示独立处理。牌桌会显示模型连接、分析和接收状态及剩余等待时间，可取消提示或让本地电脑代打当前回合。连接等待最多 7 秒，已开始接收的响应连续 10 秒无数据时提前结束等待，仍在生成首段回复时沿用整次 45 秒上限。API 地址使用 HTTPS，本机模型地址可用 HTTP。密钥保存在本机设置中，备份会去掉密钥并关闭 API。局域网房间可从同网 Dorm 客户端搜索，也可分享网页链接或二维码，网页访客可跳过寝室身份认领。牌桌端口独立于寝室工作台。

在「斗地主 → 电脑 API」中填入密钥后，可点「获取模型」从服务商返回的列表选模型，也可手动填写。接口公布思考等级时，设置页按该模型显示可选等级和服务端默认值。仅提供模型名称的服务可使用服务端默认配置，或调整后点「测试连接」。测试使用当前配置发送一条简短消息并显示响应耗时。官方预设为 DeepSeek `deepseek-flash`、OpenAI `gpt-6-luna` 和 Anthropic `claude-sonnet-5-5`。

可选择叫分或叫地主。叫地主模式下，第一个叫地主的座位成为地主，底分为 1。任一模式下全桌弃叫会重新发牌，第三次重发后由该手首个座位担任地主。首个座位可每局随机，也可由上一局最先出完的人担任。固定局数可设为 1 至 30 局或不限。普通炸弹和连炸按总张数提高倍率。4 至 5 张为 ×2，6 至 7 张为 ×4，8 至 9 张为 ×8，以此类推。单王炸为 ×8，每多一对王再翻一档，双王炸为 ×16。春天或反春再翻倍。每局结算揭晓各家余牌和本局分，打完设定局数后显示累计排名。[浙江大学智力运动会斗地主计分规则](https://mse.zju.edu.cn/_upload/article/files/98/21/4d4cd29e4ecb841f5c14bb54499c/fa1f054b-5b23-4432-87f1-5df1219e3b33.pdf)

房主可以开启全员记牌器。各座位看到的是自己还没见过的点数张数，含未公开的弃牌和底牌。玩家可以随时选择「本地托管」或「API 托管」，其他座位会看到对应的托管模式与状态。房主开启电脑 API 后，玩家可以请求带解释的 AI 提示；每次点「AI 提示」或「重新生成」都会重新调用模型，结果按建议动作、出牌牌面和理由展示。当 AI 建议出牌时会自动选中对应手牌，建议「不出」时则不会自动选牌。上下文按座位和牌局隔离，模型读取该座位的手牌、本局公开出牌、各家剩余张数与房间规则。建议需由玩家自己确认出牌。Windows 牌桌可用全屏按钮或 F11 切换全屏，退出牌桌后会恢复原窗口状态。


支持 2 至 8 人、1 至 4 副牌、经典、单癞子和天地癞子。可调整随机舍弃张数、选择平分或随机给一位玩家全部余牌，也可以关闭地主或关闭底牌。地主局采用叫分、炸弹翻倍与春天结算，无地主局先出完者获胜。房间可聊天、丢番茄并切换音效。打开右上角「牌桌消息」，可在「聊天」和「系统」之间切换。聊天保留本房间最近 80 条消息，显示发送时间和 AI 所回复的原消息。其他真人及 AI 发言会更新未读数，进入聊天页后清除。系统记录不触发聊天提醒。

有 API 电脑时默认启用 AI 回复。房主也可以在聊天里手动开关。开启电脑 API 后，没有 API 电脑的牌桌可用「AI 助手」，其上下文只包含公开信息。有 API 电脑时由其中一位回复，并使用该座位自己的手牌。回复会参考桌面牌、各座位已出的牌和剩余张数、房间规则，以及当前一局最近 24 条公开聊天。新一局开始时重置模型的聊天上下文。面板显示等待、排队和失败原因。失败时，发言者或房主可以点「重试」。

创建或调整房间时可以开启连炸，或者关闭四带二和四带两对。连炸由 3 至 A 范围内两组或更多相邻点数组成，每组张数相同且至少四张，允许用癞子补牌。例如五张 5 加五张 6 是五张二连炸。普通炸弹和连炸先比总张数，同张数时连炸更大。例如 13 张硬炸可压过两组各 4 张的二连炸。同为连炸且总张数相同时，先比组数，再比软硬和最高点数。「王炸大于连炸」开启时王炸优先。关闭时，王炸按 8 张的等级比较，排在同级普通炸弹和连炸之间，王对数越多越大。新建房间默认开启连炸与两种四带二。牌桌显示连炸开关状态，选中被房间规则禁用的连炸、四带二或四带两对时会提示对应规则。普通牌只比较同牌型、同长度组合的主牌点数，带牌的点数不影响大小。连炸的癞子只要保留原点数就按硬连炸判断。选牌存在多种合法解释时，选择框显示比较用的主牌点数、炸弹等级和癞子变换。

网页横屏牌桌用内置 Canvas 绘制。手机可以使用「全屏」，浏览器未切换物理方向时牌桌仍按横向尺寸显示。点选或拖过手牌即可多选，支持提前选牌。选牌抬起时保留相邻牌的点数可见。自己的出牌显示在操作区上方，对手的出牌靠对应座位一侧。「不要」与「管上」使用不同颜色。标准手牌保持一排，牌多时自动分成两排。可从「更多」展开手牌、查看上一手或离开房间。

连接同一 GitHub 仓库并拥有写权限后，室友的在线房间会和局域网房间一起显示。在线牌桌采用独立的 \`dormos-card-rooms\` 分支，通常间隔约七秒轮询，出牌和响应可能跨越多轮同步。房主需保持 Dorm 运行。仓库保存大厅标题、人数等资料，私人手牌和操作消息通过每个座位的加密通道传输。网页牌桌通过局域网连接房主，Git 联机由原生客户端承载。

房主可以从牌桌菜单进入「调试」。三人局以左侧为 A、自己为 B、右侧为 C，两人局的唯一对手为 A。房主可用 `/give A black_joker 1` 发一张小王，用 `/invsee A on` 打开查看权限，然后点座位和手牌删除指定牌。可用 `/forceout B on` 忽略上家的牌型和大小限制，或用 `/giveout B 33334444` 在自己回合直接打出指定的合法组合，`BR` 代表一对大小王。可用 `/add B 33334444` 一次添加多张牌，支持 10、J、Q、K、A、2 和大小王 B、R。输入 `/gui on` 后可从右上角进入 Cheats，也可直接点座位。面板可以切换查看权限、强制出牌、点选牌面添加或输入紧凑牌串。删牌时可以点选多张牌，选中的牌会用金色边框和勾标出，再一次删除。用 `/gui off` 关闭入口。命令和手牌查看结果仅在房主视角显示，正常的牌数和出牌照常广播。

经典牌型参考 [JJ 斗地主帮助](https://www.jj.cn/news/320/20110920103700018196.shtml)。多副牌和长炸弹参考 [波克癞子斗地主说明](https://www.pook.com/games/lzddz.html)，Dorm 自定义房间使用自己的余牌、王炸和癞子约定。王炸由等量的大小王构成，数量更多更大；普通炸弹按张数、软硬程度和点数比较。癞子不能替代王，单出保持原点数。
